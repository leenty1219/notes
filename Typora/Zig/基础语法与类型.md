# Zig 基础语法与类型

> Zig 示例优先采用小型、容易看懂的语言片段。Zig 版本迭代较快，尤其标准输入输出 API 和 `build.zig` 结构可能变化。运行前用 `zig version` 确认版本，并查阅该版本的 [Language Reference](https://ziglang.org/documentation/) 与标准库文档。本篇使用 `std.debug.print` 演示输出，避免把特定版本的通用 I/O 接口当成长期不变语法。

## 一个最小程序

```zig
const std = @import("std");

pub fn main() void {
    std.debug.print("Hello, Zig!\n", .{});
}
```

保存为 `main.zig`，运行：

```bash
zig version
zig run main.zig
zig build-exe main.zig
./main
```

`@import` 是编译器内建函数，用于导入模块；`std` 是标准库。`pub fn main()` 声明公开入口。格式化字符串后的 `.{}` 是匿名 struct 参数，用作格式化参数元组；没有插值参数时传空元组。

## const 与 var

`const` 绑定不可重新赋值，`var` 绑定可重新赋值。Zig 要求编译器确认 `var` 确实被修改，否则会报错，提醒将其改成 `const`。

```zig
const language = "Zig";
var count: u32 = 0;
count += 1;

std.debug.print("{s}: {d}\n", .{ language, count });
```

常见格式占位符：`{s}` 表示字符串，`{d}` 表示十进制整数，`{x}` 表示十六进制，`{}` 用于有默认格式的值。格式字符串参数必须匹配。

常量不是“编译期常量”的同义词；需要明确要求编译期求值时使用 `comptime`。

## 基本类型与字面量

常见类型：

- 有符号整数：`i8`、`i16`、`i32`、`i64`、`i128`、`isize`。
- 无符号整数：`u8`、`u16`、`u32`、`u64`、`u128`、`usize`。
- 浮点数：`f16`、`f32`、`f64`、`f80`、`f128`（平台支持情况不同）。
- 布尔：`bool`；字符通常用 UTF-8 字节切片表示，而不是独立的 Unicode `char` 类型。
- `void`：无有意义的值，常见于不返回数据的函数。
- `noreturn`：函数不会正常返回，例如调用 `unreachable` 或无限循环。

整数位宽写在类型名中，许多字面量的类型可由上下文推断。需要表达特定位宽时显式标注：

```zig
const signed_value: i32 = -12;
const byte: u8 = 255;
const mask = @as(u32, 1) << 8;
```

Zig 不会隐式放宽数值类型。整数转换需要使用 `@intCast` 等内建操作，并由上下文提供目标类型；可能超出范围的输入应先验证或使用适当的溢出检查操作。不要把窄化转换当作安全的自动转换。

## 数组、切片和字符串

数组长度属于类型的一部分，切片则是指针和长度的视图：

```zig
const values = [_]u32{ 10, 20, 30 };
const middle = values[1..3];

std.debug.print("len={d}, first={d}\n", .{ middle.len, middle[0] });
```

`[_]T{...}` 根据元素推断数组长度；`values[1..3]` 生成切片，结束下标不包含在内。切片本身不拥有数据，必须保证底层数组仍有效。

Zig 字符串字面量通常是以零结尾的字节数组指针（常见类型形式 `*const [N:0]u8`），可通过切片形式传给接受字节切片的 API。UTF-8 文本本质是字节序列，不要把字节索引当作 Unicode 字符索引。

```zig
const greeting = "hello";
const bytes: []const u8 = greeting;
std.debug.print("{s}\n", .{bytes});
```

具体 coercion/数组指针规则可能显得不直观，遇到类型错误时可显式写出目标切片类型。

## 指针

`*T` 是单项指针，指向一个 `T`；`[]T` 是多项切片，包含指针和长度；`[*]T` 是哨兵/多项指针形式之一，使用时需要额外管理长度边界。指针类型形式携带不同的边界信息。

```zig
var value: i32 = 10;
const pointer: *i32 = &value;
pointer.* = 20;

std.debug.print("{d}\n", .{value});
```

`&value` 取地址，`pointer.*` 解引用。指针是否可空由类型区分：普通指针不能表示 null；可空指针写成 `?*T`。不要解引用悬垂指针或越界指针；Zig 不会像 Rust 借用检查器那样静态证明所有指针都有效。

## 函数

函数参数和返回类型都写在签名中：

```zig
fn add(a: i32, b: i32) i32 {
    return a + b;
}

pub fn main() void {
    const result = add(2, 3);
    std.debug.print("{d}\n", .{result});
}
```

函数默认不是公开的；跨模块访问需要 `pub`。Zig 支持泛型风格函数，常通过 `anytype` 参数和 `@TypeOf` 等编译期能力构造，具体用法见 comptime 章节及官方语言参考。

## 控制流

`if` 和 `switch` 都是表达式，可以产生值。`switch` 分支需要覆盖所有可能情况，或使用 `else`：

```zig
const score: u8 = 85;
const grade = if (score >= 60) "pass" else "fail";

const description = switch (score) {
    0...59 => "needs work",
    60...100 => "passed",
};
```

`for` 可遍历数组或切片；`while` 适合条件循环。循环可以带继续表达式：

```zig
const values = [_]u32{ 1, 2, 3 };
var sum: u32 = 0;
for (values) |value| {
    sum += value;
}
```

`|value|` 是捕获每轮的元素。需要索引时可使用索引捕获语法，具体形式可查当前版本语言参考。

## 结构体与方法

Zig 使用 `struct` 聚合数据。Zig 没有独立的 `impl` 语法；在结构体命名空间内定义函数，将指针作为首个参数即可形成常见方法调用形式。

```zig
const Rectangle = struct {
    width: u32,
    height: u32,

    pub fn area(self: Rectangle) u32 {
        return self.width * self.height;
    }
};

const rect = Rectangle{ .width = 10, .height = 5 };
const area = rect.area();
```

字段初始化使用 `.field = value`。若方法需要修改结构体，可接收 `*Rectangle`，并通过可变绑定调用。

## enum 与 tagged union

`enum` 表示一组离散标签：

```zig
const Color = enum { red, green, blue };
const color: Color = .green;
```

带数据的变体用 tagged union，类似“标签 + 对应数据”：

```zig
const Message = union(enum) {
    quit,
    move: struct { x: i32, y: i32 },
    write: []const u8,
};

fn describe(message: Message) void {
    switch (message) {
        .quit => std.debug.print("quit\n", .{}),
        .move => |position| std.debug.print("move {d},{d}\n", .{ position.x, position.y }),
        .write => |text| std.debug.print("{s}\n", .{text}),
    }
}
```

通过 `switch` 检查每个变体，编译器可验证分支覆盖。tagged union 常用于表达互斥状态，避免用多个布尔字段表示彼此冲突的状态。

## 可选值与错误联合

`?T` 表示值可能存在也可能为空，用 `null` 表示缺失：

```zig
fn find_port(configured: bool) ?u16 {
    if (configured) return 8080;
    return null;
}

if (find_port(true)) |port| {
    std.debug.print("port={d}\n", .{port});
} else {
    std.debug.print("no port\n", .{});
}
```

`!T` 表示结果可能是错误，也可能是 `T`。函数可定义错误集合：

```zig
const ParseError = error{ EmptyInput, InvalidNumber };

fn parsePort(text: []const u8) ParseError!u16 {
    if (text.len == 0) return error.EmptyInput;
    return std.fmt.parseInt(u16, text, 10) catch error.InvalidNumber;
}
```

调用者可以用 `try` 将错误向上传播，或用 `catch` 处理：

```zig
fn start() !void {
    const port = try parsePort("8080");
    std.debug.print("port={d}\n", .{port});
}
```

`try expression` 在成功时取出值，在错误时从当前函数返回错误。`catch` 可提供默认值或执行错误分支。错误联合不是异常：调用链上的错误需要显式传播或处理。

## defer 与资源清理

`defer` 在当前作用域退出时执行，常用于释放资源；多个 defer 按后进先出执行。

```zig
fn example() void {
    defer std.debug.print("最后执行\n", .{});
    std.debug.print("先执行\n", .{});
}
```

资源释放应与分配配对。即使使用 `defer`，也要确认清理语句注册的位置覆盖所有提前返回路径。

## allocator 与内存管理

Zig 不提供自动垃圾回收，也没有 Rust 式所有权/借用检查器。许多标准库容器需要显式 allocator。常见模式是调用方传入 allocator，让内存生命周期和策略明确：

```zig
const std = @import("std");

fn buildMessage(allocator: std.mem.Allocator) ![]u8 {
    return try std.fmt.allocPrint(allocator, "value={d}", .{42});
}
```

调用者负责释放返回的内存：

```zig
const allocator = std.heap.page_allocator;
const message = try buildMessage(allocator);
defer allocator.free(message);
```

这个片段展示 allocator 约定，不代表生产代码都应使用 `page_allocator`。实际程序通常在合适作用域创建 arena 或使用通用 allocator，并按 API 约定释放。容器在不同版本中的初始化、释放 API 有变化，查对应版本文档。

需要持续问自己：谁提供 allocator？分配的数据由谁释放？它会活多久？错误提前返回时是否仍会释放？测试时可用检测泄漏的 allocator 辅助发现问题。

## 编译期计算 comptime

Zig 的 `comptime` 要求表达式在编译期间求值，常用于类型生成、泛型逻辑和常量计算：

```zig
fn makeArray(comptime length: usize) [length]u8 {
    return [_]u8{0} ** length;
}

const buffer = makeArray(16);
```

`length` 是 comptime 参数，数组长度因此可成为类型的一部分。编译期能力很强，但过度使用会让错误信息复杂；先写普通函数，只在需要编译期已知类型或值时使用 `comptime`。

## C 互操作概览

Zig 可以导入 C 头文件并调用 C API，常见入口是 `@cImport`。这对复用系统库和现有 C 库有用，但涉及构建时头文件、链接库、ABI 和平台差异：

```zig
const c = @cImport({
    @cInclude("stdio.h");
});
```

真实项目需要在构建系统中配置 include path 和链接参数；做跨平台绑定前确认 C API 的内存所有权、错误约定和 ABI。

## 构建、运行与测试

```bash
zig run main.zig          # 编译并运行
zig build-exe main.zig    # 构建可执行文件
zig test main.zig         # 运行内嵌测试
zig fmt main.zig          # 格式化
```

测试可写在源码中：

```zig
test "addition" {
    try std.testing.expectEqual(@as(i32, 5), add(2, 3));
}
```

大型项目用 `build.zig` 描述构建步骤；构建系统 API 曾随 Zig 版本演进，不能假设网上不同年份的 `build.zig` 可以直接混用。先用本机安装版本的官方模板和文档。

## 常见问题

| 现象 | 常见原因 | 检查方向 |
| --- | --- | --- |
| `local variable is never mutated` | `var` 实际没有修改 | 改为 `const` |
| 格式化参数类型错误 | 占位符与参数不匹配 | 检查 `{s}`、`{d}` 及参数元组 |
| 整数转换报错 | Zig 不隐式转换位宽 | 显式转换并验证范围 |
| 切片越界或指针无效 | 长度边界或生命周期管理错误 | 检查底层存储是否有效、索引是否在范围内 |
| 内存泄漏 | 分配后未释放或错误路径漏清理 | 使用 `defer`，明确 allocator 和所有者 |
| 教程代码无法编译 | 教程针对不同 Zig 版本 | 核对 `zig version` 与教程发布版本 |
| `build.zig` API 找不到 | 构建系统版本不匹配 | 使用当前版本 `zig init` 模板和对应文档 |

## 练习

1. 写一个根据输入分数返回等级的函数，使用 `if` 和 `switch`。
2. 用 struct 建模二维点，实现距离平方方法。
3. 用 tagged union 表示命令（退出、移动、打印），通过 `switch` 处理。
4. 写一个返回错误联合的解析函数，分别处理空输入和无效输入。
5. 使用 allocator 创建动态字符串，确保成功和错误路径都正确释放。
6. 阅读 Ziglings，按本地版本选择对应内容，并把每道题的关键点补充到此文档。
